# Заказы Мекеги в реальном времени

Сервер принимает заявки с сайта/Telegram, хранит их в SQLite и отправляет изменения авторизованным сотрудникам через SSE. Сайт остаётся на GitHub Pages. Node.js 24, дополнительных пакетов нет.

## Размещение

Нужен сервер с HTTPS и постоянным диском. GitHub Pages не исполняет этот код. Внешний сервер пока не настроен.

Переменные окружения:

- `ADMIN_TOKEN` — случайный ключ не короче 32 символов. Хранить только в секретах сервера; не добавлять в HTML или репозиторий.
- `ALLOWED_ORIGINS` — разрешённые адреса через запятую, для текущего сайта `https://jonessssenator-art.github.io`.
- `DATA_DIR` — папка базы на постоянном диске, например `/data`.
- `PORT` — порт сервера, по умолчанию `8787`.
- `HOST` — по умолчанию `127.0.0.1`, в Docker `0.0.0.0`.

Запуск: `npm start`. В папке есть Dockerfile. Настройте HTTPS reverse proxy, отключите буферизацию для `/api/events`, разрешите длительные соединения. Том `/data` должен сохраняться при перезапуске и развёртывании. Запускайте один экземпляр сервера с этой базой; для нескольких экземпляров нужен общий брокер событий.

## Подключение макета

В `index.html` заполните `window.MEKEGI_API_URL` HTTPS-адресом сервера без завершающего `/`. В исходном проекте это `mockups/index.html`; после изменения выполните `python3 mockups/build_standalone.py` и опубликуйте результат как `index.html`.

В CRM появится «Войти в CRM». Ключ сотрудник вводит в этой форме; он хранится только до завершения сессии браузера. Клиентам ключ не нужен. Заказы посетителей не доступны через публичный список. По отдельному случайному токену посетитель может получить статус только своего заказа.

Без адреса сервера макет работает в демо-режиме. Изменения синхронизируются между вкладками одного браузера через событие `storage`; это НЕ синхронизация между телефонами.

## Проверено

`npm test`: авторизация, CORS, создание и сохранение заявки, серверный расчёт суммы, защита от повторной отправки, отправка обновления SSE, изменение статуса, изоляция данных клиента и сохранность после перезапуска.

В интерфейсе локально проверены две отдельные вкладки: создание заявки клиентом и появление в CRM без перезагрузки.

Это демонстрация, с примерными ценами. Для реального бизнеса нужны утверждённый прайс, согласованный порядок обработки персональных данных, резервное копирование и отдельные учётные записи сотрудников. Текущий ключ даёт полный доступ сотруднику; публично его не передавать.
